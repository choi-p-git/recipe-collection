## Important Current Decision

Do not make users review every Recipe Collection base food. Production DBs may have thousands of ingredients, kitchen food items, and non-food items.

Catalog review should be demand-driven:

- current planning-window items
- explicit review-needed rows
- invoice/catalog ingest rows
- auto/vendor-derived matches
- active blocker rows for ordering, costing, or invoice reconciliation

`scope=all` is audit/debug only.

## Invoice Pipeline Direction

The next major workflow should scaffold invoice/catalog staging, not full accounting.

Company workflow target:

- Vendors may provide digital invoice APIs, CSV exports, PDF invoices, or emailed invoice attachments.
- Ingest parses line items with vendor, invoice identity, SKU/item/catalog id, product category code, item name, pack-size description, quantity, unit, and unit price.
- Vendor product category code maps through admin-maintained vendor category flags/rules.
- Matching should use vendor item id/catalog id first, then existing inventory catalog vendor-code links, then reviewable name/category matching.
- If an invoice line is not already matched to current inventory, prompt the user to add/link the item to the correct inventory sub-location.
- Once linked, invoice history should be tagged to the inventory/catalog item.
- Inventory automation should migrate away from seed Recipe Collection items as catalog truth and toward invoice/catalog-driven item establishment.
- Automatic invoice/order generation for menu-needed items comes later, after invoice staging, matching, location-link prompts, and reorder planning contracts are stable.
